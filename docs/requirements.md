# A-GP 插件系统需求

> **唯一事实来源**：本文档。所有参与开发的（Muse、GPT 侧、未来协作者）都以此为准，不要各记一份。
> 立项：2026-10-12（用户亲口定）。更新记录见文末。

## 背景

A-GP 是身体（成熟图表/数据/插件），Muse 是灵魂（学习进化、实时信号、模拟验证）。
一切量化输出（指标/策略/信号）最终为 A-GP 服务，在它上面运行。
铁律：A-GP 主线不可直接修改；这次是最后一次动核心，之后所有迭代都在核心之外。

## 仓库约定（G-Lcn/Muse-Ai）

- `signals/`：信号数据 JSON，Muse 在交易日每分钟推送一次
- `plugins/`：插件 JS 文件
- `manifest.json`：插件清单（id、版本、入口文件、挂载槽位、所需 API 版本）
- `docs/`：本文档等说明

## 需求 1：远程插件加载器（双层）

A-GP 核心只做一次改动：加一个插件加载器。之后插件 100% 在核心之外迭代。

- **① 远程层**：A-GP 启动拉取 `manifest.json`，按需加载 entry JS，调 `registerPlugin` 挂进四个槽位（分时主图/副图、K线主图/副图）。manifest 可并列多版本，用户一键切换回滚。
- **② 手动上传层**：A-GP 界面提供"上传插件"入口，用户选本地 .js 文件，加载器基本校验后注册进指定槽位；localStorage 持久化，支持启用/禁用/删除；手动插件 id 独立命名空间。

## 需求 2：插件管理端独立

A-GP 界面内独立的"插件管理"面板：统一列出所有插件（远程订阅 + 手动上传），显示名称、版本、来源、挂载槽位、启用状态；支持启用/禁用/删除。手动上传的真删除（清 localStorage）；远程的删除 = 退订（本地不再加载，仓库文件不动）。远程插件可从 manifest 浏览、一键订阅。

## 需求 3：插件 API 说明（一页纸，待写）

本地自用，不搞复杂。只讲三件事：插件长什么样（一个注册约定）、四个槽位分别能干什么、怎么挂上去。正文随 A-GP 源码（它是 A-GP 的契约），本仓库放开发指引并链接过去。

## 需求 4：整体性治理（简化版）

最终呈现必须是一个整体，不允许随意放位置：

- 槽位纪律：四个槽位由插件管理端统一分配；同槽位多插件走层叠/互斥规则，插件不许自己抢位置。
- 视觉一致：主图标记沿用现有标签风格（激进做T/保守做T），配色字号统一，不破坏 K 线/均线/价格轴原有布局。
- 不做的：安全边界长篇、发布评审制、SRI/SHA 锁定（本地自用，信任链短）。
