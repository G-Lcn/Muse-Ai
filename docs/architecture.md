# 架构总览

> 本文档描述 A-GP 插件系统整体架构。

**定位（用户亲口定）：A-GP 一直是基座，插件就是生态。**
基座求稳、极少改动；生态求活、持续生长。基座为生态提供四个槽位和加载器，
生态为基座带来信号、指标和玩法。两者通过 manifest 契约连接，互不侵入。

## 数据流（信号）

```
行情源(腾讯/新浪/东财) → Muse 信号计算 → signals/<代码>.json → GitHub
    → A-GP 插件轮询(约1分钟) → 分时主图画买卖点标记 / 副图显示评分
```

- 推送频率：交易日每分钟一次；端到端延迟约 1-3 分钟。
- 插件发现数据超过 5 分钟未更新，显示"信号离线"，不画过期标记。

## 代码流（插件）

```
Muse/协作者开发插件 → push 到 plugins/ + 更新 manifest.json
    → 用户刷新 A-GP → 加载器拉清单 → 注册进槽位
```

- 用户也可在管理面板手动上传本地 .js（localStorage 持久化）。
- 视觉规范：主图标记沿用"激进做T/保守做T"标签风格，不破坏原有布局。

## 协作约定（多地/多人开发）

1. `docs/requirements.md` 是唯一事实来源，动手前先读。
2. 改 A-GP 核心的需求先跟用户确认（铁律：最后一次动核心）。
3. 插件只动 `plugins/` + `manifest.json`，不动核心。
4. 信号数据只写 `signals/`，固定 JSON 格式（格式见 requirements）。
5. 文档和代码一起提交，不留"口头约定"。
